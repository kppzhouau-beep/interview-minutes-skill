# 企业与机构名称核验协议

外部核验只用于确认转写中的主体名称，不用于给纪要增加新事实。

## 名称核验表

写作前提取原始转录和拟成稿中的公司、机构、品牌及简称，记录原始位置、候选写法、核验来源和最终处理。只核验计划保留在正文中的主体。

## 来源分流

1. 国内企业：企查查或同类工商数据库，加公司官网、政府、交易所或监管机构等权威来源。
2. 政府、科研院所和高校：官方网站，加主管部门、权威名录或其他权威公开来源。
3. 国外企业：公司官网，加监管披露、行业协会、标准组织或权威行业来源。
4. 无法可靠验证且不影响主旨：省略争议名称或泛化为“相关厂商／供应商／科研院所”。

两个相互转载或来自同一底层材料的网页不算独立来源。只有“转录确实提及”和“名称核验通过”同时满足时，才写入准确名称。

## 企查查 MCP 稳定调用协议（强制）

只要运行环境具有合法可用的企查查 MCP，国内企业名称核验必须优先使用。不得因当前会话的工具目录暂未显示 QCC 工具，就直接宣布企查查不可用。必须按以下顺序执行：

1. **原生工具优先**：在当前可调用工具中搜索 `qcc`、`企查查` 及 `qcc-company`。若已暴露相应工具，直接使用原生 MCP 工具，不走备用脚本。
2. **识别“零工具”故障**：若 Codex 配置中的 `mcp_servers.qcc-*` 为 `enabled = true`，且所需令牌环境变量已设置，但当前工具清单没有任何 QCC 工具，将其判定为客户端工具发现／会话缓存问题，而不是企查查服务不可用。禁止输出、记录或提交 Token 原文。
3. **直连备用发现**：读取当前 Skill 的 `scripts/qcc_mcp_call.py`，使用 `--server qcc-company --list-tools` 完成标准 MCP 初始化、会话 Cookie 保持和 `tools/list`。返回工具数量大于 0 时，可继续使用该脚本调用必要工具。如需外网权限，按宿主环境的正常批准流程申请，不得绕过权限管理。
4. **实体路由必须正确**：简称、品牌名或不完整主体先调 `get_company_by_query`，原始查询字符串不得擅自补全；返回多候选时必须由用户选定，不得自动选第一个。已有工商全称时可调 `get_company_registration_info`；只有同时掌握“全称＋统一社会信用代码”时才调 `verify_company_accuracy`。
5. **最小调用**：名称核验只调实体识别或登记信息工具，不得为求“全面”扫描股东、诉讼、风险、知识产权等与纪要名称核验无关的数据。
6. **有界重试与降级**：直连路径因网络、授权或服务端错误失败时，仅允许对同一请求再重试 1 次。两次均失败后才进入公开页面替代核验，并在内部核验表和交付说明中准确记录失败类型。不得将“工具目录 0 个”单独视为降级依据。
7. **追溯要求**：内部名称核验表记录实际调用的 Server、tool name、查询键、候选与核验结果；正式纪要只保留经核准的名称，不写调用过程、查询失败或工具说明。

## 企查查不可用时的替代核验

只有原生调用与直连备用路径都失败，或团队本身没有企查查权限时，才使用公开页面或 `site:qcc.com` 检索，并与国家企业信用信息公示系统、公司官网、政府、交易所或监管机构等一手来源交叉验证。不得伪称已调用企查查 MCP。

## 交付前复核

重新提取最终正文中的全部主体名称，与名称核验表逐项核对。任何新增但未经核验的名称必须删除、泛化或完成核验后再交付。
