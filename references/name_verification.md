# 企业与机构名称核验协议

外部核验只用于确认转写中的主体名称，不用于给纪要增加新事实。

## 名称核验表

写作前提取原始转录和拟成稿中的公司、机构、品牌及简称，记录原始位置、候选写法、核验来源和最终处理。只核验计划保留在正文中的主体。

## 来源分流

1. 国内企业：企查查或同类工商数据库，加公司官网、政府、交易所或监管机构等权威来源。
2. 政府、科研院所和高校：官方网站，加主管部门、权威名录或其他权威公开来源。
3. 国外企业：公司官网，加监管披露、行业协会、标准组织或权威行业来源。
4. 无法可靠验证且不影响主旨：省略争议名称或泛化为“相关厂商／供应商／科研院所”。

两个相互转载或来自同一底层材料的网页不算独立来源。只有“转录确实提及”和“名称核验通过”同时满足时，才写入准确名称。

## 企查查 MCP（可选）

如果运行环境已配置企查查 MCP：

1. 优先调用原生 MCP 工具。
2. 简称或品牌先调用实体搜索；多候选时不得自动选择第一个。
3. 已有工商全称时查询登记信息；只有同时掌握全称和统一社会信用代码时才做准确性校验。
4. 仅查询名称识别和登记信息，不扫描诉讼、股东、风险或知识产权等无关数据。
5. 内部核验表记录实际 Server、工具名、查询键和结果；正式纪要不记录调用过程。

若 Codex 已配置相关 Server 但当前会话未发现工具，可使用 `scripts/qcc_mcp_call.py --server qcc-company --list-tools` 做一次直连发现。该脚本从配置文件读取 Server URL，并从环境变量读取 Token；不会打印 Token。网络或授权失败只重试一次，随后改用公开页面加权威一手来源。

如果团队没有企查查权限，使用其他合法工商数据库和权威一手来源即可，不得伪称已调用企查查。

## 交付前复核

重新提取最终正文中的全部主体名称，与名称核验表逐项核对。任何新增但未经核验的名称必须删除、泛化或完成核验后再交付。
